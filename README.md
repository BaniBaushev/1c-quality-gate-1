# 1c-quality-gate

Плагин Claude Code для контроля качества разработки на 1С:Предприятие.

Проверяет четыре измерения — **стандарты разработки**, **принципы структурного и
объектно-ориентированного программирования**, **паттерны проектирования применительно к 1С**
и **корректность XML-структур метаданных**, — а главное, не даёт объявить работу
законченной, пока проверка не прогнана.

> **Статус: 0.6.0.** Все четыре контура работают, контур кода переведён на статический
> анализатор. Установка с GitHub и обновление проверены; прогон проверен на выгрузках
> типовой конфигурации и на боевых расширениях. 98 автотестов, новые проверяются мутациями.

## Зачем ещё один линтер

Затем, что это не линтер. Статические анализаторы для BSL существуют и хорошо делают свою
работу — плагин их запускает, а не заменяет. Он добавляет четыре вещи, которых у них нет.

**Проверка, которую нельзя молча пропустить.** Обычная инструкция «сверяйся со стандартами»
неисполнима по построению: её невыполнение неотличимо от выполнения. Здесь правка файла 1С
взводит гейт, а `Stop`-хук блокирует завершение сессии, пока гейт не снят. Снять его можно
только предъявив след проверок, который проверяется валидатором.

**Честность про непроверенное.** Компилируемость тел BSL-модулей не проверяется ни загрузкой
конфигурации из файлов, ни выгрузкой, ни валидаторами XML: они разбирают структуру, а тела не
компилируют. Синтаксическая ошибка внутри процедуры проходит их все и всплывает лишь при
инициализации модуля в базе. Плагин обязан это заявить: вердикт «Чисто» без записи
`not_verified` валидатор отклоняет.

Тот же принцип действует на каждую внешнюю зависимость. Нет анализатора, нет Python, нет
индекса кода — контур пропускается **с явной записью в следе**, а не тихо.

**Часовой против ложной зелени.** Инструмент, который работает, но ничего не находит,
неотличим от инструмента, который сломан. Поэтому вместе с рабочими файлами прогоняется
фикстура с заведомым нарушением, и притом такая, которая требует диагностики **по
метаданным**: при потере контекста конфигурации гаснет именно этот класс проверок, а
остальные замечания продолжают приходить, и отчёт выглядит рабочим.

**Градация вместо «всё или ничего».** Полный прогон на правке комментария — налог, из-за
которого гейт начинают обходить. Глубина считается по трём осям и для мелкой правки занимает
секунды.

## Как определяется глубина

Три оси, считаются один раз до запуска контуров:

- **Объём** (C0…C3) — сколько тронуто и пересекает ли правка границы модулей и метаданных.
- **Архетипы кода** — множество меток, не шкала: запрос, транзакция, запись наборов,
  обработчик события, интеграция, права, CFE-перехват, модуль формы и другие. Одна правка
  может нести несколько меток сразу.
- **Сложность** — вложенность, длина метода, число параметров, цепочки ветвлений.

Итог: `глубина = max(по объёму, по архетипам, по сложности)`.

Смысл второй оси в асимметрии: **три строки внутри транзакции опаснее трёхсот строк
переименований**, но при этом транзакции нужен глубокий разбор кода, а новому общему модулю на
тридцать строк — разбор архитектуры. Одномерный «множитель риска» этого не выражает.

## Установка

```text
/plugin marketplace add Romandredan/1c-quality-gate
/plugin install 1c-quality-gate
```

После установки перезапустите сессию — навыки материализуются при старте.

Обязательная зависимость одна: MCP-сервис стандартов `v8std`, он объявлен в самом плагине и
работает по HTTP без настройки. **Статический анализатор плагин ставит сам** при первом
прогоне: скачивает закреплённый релиз, сверяет SHA-256 и кладёт в свой каталог данных. Python
(валидаторы XML), индекс кода и справочник API платформы — опциональны и усиливают проверки.
Подробности — в [docs/INSTALL.md](docs/INSTALL.md).

## Использование

Обычно вмешательство не требуется: правка файла 1С взводит гейт, а перед завершением работы
агент сам прогоняет `quality-gate`. Вручную:

```text
/gate            # прогнать проверку и снять гейт
/gate-status     # посмотреть, что ждёт проверки
/gate --deep     # поднять глубину против расчётной
```

## Борьба с ложными срабатываниями — часть конструкции

Ложная находка вреднее пропущенной: она провоцирует переделку рабочего кода, и после двух-трёх
таких проверку отключают целиком. Поэтому:

- **состав проекта определяется автоматически** — основная конфигурация подключается к анализу
  вместе с расширениями. Расширение, разобранное в одиночку, не видит библиотек, и каждое
  обращение к ним становится «неразрешённым вызовом»: на боевых расширениях это была треть
  всех находок;
- **неразобранные файлы называются неразобранными**, а не источником трёхсот проблем: их
  замечания получены на обрывке синтаксического дерева и снимаются целиком;
- **диагностики с высокой долей ложных на идиоматичном 1С отключены** в гейтовом конфиге, а
  типографика и форматирование вынесены в отдельный дешёвый контур;
- у каждого архитектурного признака обязателен **контр-сигнал** — законная форма, в которой
  это не дефект.

Замеры на боевом коде: [docs/false-positives-cfe.md](docs/false-positives-cfe.md).

## Из чего собрано

| Контур | Что делает |
|---|---|
| `quality-gate` | оркестратор: три оси, выбор глубины, сборка следа |
| `bsl-code-review` | статический анализ + антипаттерны и механика платформы + ревью логики |
| `bsl-architecture-review` | SOLID, GRASP, паттерны применительно к 1С; десять признаков с порогами и контр-сигналами |
| `xml-structure-review` | валидация метаданных, файлы-сироты, права ролей |
| `file-hygiene` | кодировки, BOM, запрещённые символы |

Отдельный справочник — **антипаттерны кода, порождаемого языковой моделью**: запись набора с
удалением по неполному отбору, отчёт о непрогнанной проверке, «зелёная» сборка вместо проверки
компилируемости, отсутствие `Знач` у немутируемых коллекций, разбор одного payload в нескольких
местах. Типовые своды их не содержат — они описывают ошибки людей.

## Лицензия и источники

Код, скрипты, чеклисты, карты соответствий и эвристики — MIT.

Тексты стандартов разработки 1С здесь **не воспроизводятся**: плагин публикует только ссылки и
номера вида `#stdNNN`, а сами тексты получает во время работы через MCP-сервис v8std. Правила
изложены авторами своими словами со ссылкой на номер стандарта. Подробнее — в [LICENSE](LICENSE).

Статические анализаторы (`itrous/bsl-analyzer`, `1c-syntax/bsl-language-server`) не входят в
пакет и распространяются по своим лицензиям; плагин запускает их как внешние программы.
