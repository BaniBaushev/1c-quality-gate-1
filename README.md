# 1c-quality-gate

Плагин Claude Code для контроля качества разработки на 1С:Предприятие.

Проверяет четыре измерения — **стандарты разработки**, **принципы структурного и
объектно-ориентированного программирования**, **паттерны проектирования применительно к 1С**
и **корректность XML-структур метаданных**, — а главное, не даёт объявить работу
законченной, пока проверка не прогнана.

> **Статус: 0.1.0, ранняя версия.** Работает каркас — гейты, градация глубины, формат и
> валидатор следа. Контуры проверки подключаются последовательно (см. «Дорожная карта»);
> неустановленный контур честно отчитывается записью `skipped`, а не молчит.

## Зачем ещё один линтер

Затем, что это не линтер. Статические анализаторы для BSL существуют и хорошо делают свою
работу — плагин их использует, а не заменяет. Он закрывает три вещи, которых у них нет.

**Проверка, которую нельзя молча пропустить.** Обычная инструкция «сверяйся со стандартами»
неисполнима по построению: её невыполнение неотличимо от выполнения. Здесь правка файла 1С
взводит гейт, а `Stop`-хук блокирует завершение сессии, пока гейт не снят. Снять его можно
только предъявив след проверок, который проверяется валидатором.

**Честность про непроверенное.** Компилируемость тел BSL-модулей не проверяется ни загрузкой
конфигурации из файлов, ни выгрузкой, ни валидаторами XML: они разбирают структуру, а тела
не компилируют. Синтаксическая ошибка внутри процедуры проходит их все и всплывает лишь при
инициализации модуля в базе. Плагин обязан это заявить: вердикт «Чисто» без записи
`not_verified` валидатор отклоняет.

**Градация вместо «всё или ничего».** Полный прогон на правке комментария — налог, из-за
которого гейт начинают обходить. Глубина считается по трём осям и для мелкой правки
занимает секунды.

## Как определяется глубина

Три оси, считаются один раз до запуска контуров:

- **Объём** (C0…C3) — сколько тронуто и пересекает ли правка границы модулей и метаданных.
- **Архетипы кода** — множество меток, не шкала: запрос, транзакция, запись наборов,
  обработчик события, интеграция, права, CFE-перехват, модуль формы и другие. Одна правка
  может нести несколько меток сразу.
- **Сложность** — вложенность, длина метода, число параметров, цепочки ветвлений.

Итог: `глубина = max(по объёму, по архетипам, по сложности)`.

Смысл второй оси в асимметрии: **три строки внутри транзакции опаснее трёхсот строк
переименований**, но при этом транзакции нужен глубокий разбор кода, а новому общему модулю
на тридцать строк — разбор архитектуры. Одномерный «множитель риска» этого не выражает.

## Установка

```text
/plugin marketplace add Romandredan/1c-quality-gate
/plugin install 1c-quality-gate
```

После установки перезапустите сессию — навыки материализуются при старте.

Единственная обязательная зависимость — MCP-сервис стандартов `v8std`, он объявлен в самом
плагине и работает по HTTP без настройки. Опциональные внешние MCP (статический анализатор
BSL, индекс кода, справочник API платформы) заметно усиливают проверки; без них плагин
работает, честно отмечая пропущенные слои. Подробности — в [docs/INSTALL.md](docs/INSTALL.md).

## Использование

Обычно вмешательство не требуется: правка файла 1С взводит гейт, а перед завершением работы
агент сам прогоняет `quality-gate`. Вручную:

```text
/gate            # прогнать проверку и снять гейт
/gate-status     # посмотреть, что ждёт проверки
/gate --deep     # поднять глубину против расчётной
```

## Дорожная карта

| Компонент | Статус |
|---|---|
| Гейты, градация, след проверок, валидатор | готово |
| `bsl-code-review` — стандарты, антипаттерны, верификация API платформы | готово |
| `bsl-architecture-review` — SOLID, GRASP, паттерны в 1С | в работе |
| `xml-structure-review` — валидация метаданных, файлы-сироты, права ролей | спроектировано |
| `file-hygiene` — кодировки, BOM, запрещённые символы | спроектировано |

### Что уже умеет контур кода

Диагностики статического анализатора с привязкой каждого кода к номеру стандарта;
антипаттерны производительности и механики платформы (запрос в цикле, чтение реквизита через
точку, подзапрос в списке полей, порядок транзакции и попытки); верификация сигнатур API,
существования и экспортности общих модулей, состава объектов метаданных; именование и
допустимые символы; ревью логики более сильной моделью на крупных изменениях.

Отдельный файл — **антипаттерны кода, порождаемого языковой моделью**: запись набора с
удалением по неполному отбору, отчёт о непрогнанной проверке, «зелёная» сборка вместо
проверки компилируемости, отсутствие `Знач` у немутируемых коллекций, разбор одного payload в
нескольких местах. Типовые своды их не содержат — они описывают ошибки людей.
